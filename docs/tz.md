
## 📄 Техническое заание (ТЗ) на разработку проекта **«FairLabQueue Bot»**  

## 1. Общие сведения

**Наименование проекта**  
«FairLabQueue Bot» — Telegram-бот для организации и управления очередями на сдачу/приём практических работ, лабораторных и т.п.

**Назначение**  
Автоматизировать организацию очередей между студентами и преподавателями/ассистентами через удобный интерфейс Telegram. Позволяет студентам записываться в очередь, отслеживать позицию и историю, а администраторам — создавать/закрывать очереди, редактировать и формировать итоговые списки.

**Тип проекта**  
Программно-аппаратный комплекс на платформе Telegram (бот).

---

## 2. Основания для разработки и цели

### 2.1. Основания
- Заявка учебного заведения/группы на упрощение оформления очередей при приёме работ.
- Потребность в быстром и удобном способе формирования очереди без ручной сверки списков.

### 2.2. Цели разработки
1. **Облегчить процесс записи и отслеживания очереди** – студенты сами записываются, отменяют запись, видят текущую позицию.
2. **Сохранить историю позиций участников** (для последующей справедливой сортировки).
3. **Предоставить администраторам инструменты управления очередью** – создание, закрытие, удаление, финализация.

## 3. Требования к системе

### 3.1. Функциональные требования (ФТР)

#### ФТР-1 — Основной сценарий работы
1. Пользователь отправляет команду `/queue "Предмет" ДД.MM.ГГГГ ЧЧ:ММ` (например: `/queue "ООП" 05.03.2026 16:00`).
2. Бот публикует сообщение с кнопками:
   - ✅ «Участвую»
   - ❌ «Отменить участие»
   - «Удалить запись» (удаляет очередь)
   - «Завершить досрочно» (финализирует очередь)

#### ФТР-2 — Запись / отмена записи
- Нажатие «Участвую» приводит к записи пользователя в очередь.
- Нажатие «Отменить участие» — к удалению пользователя из очереди.

#### ФТР-3 — Менеджер очереди (администратор)
- Админ может:
  - создать очередь командой `/queue`,
  - закрыть очередь досрочно,
  - удалить очередь,
  - отметить «последнего» пользователя (кто успел), чтобы остальные были помечены как «не успевшие».

#### ФТР-4 — История позиций и «справедливая» сортировка
- Система ведёт историю позиции каждого пользователя по предмету.
- При генерации итоговой очереди учитывается:
  - сколько раз пользователь уже был в очереди,
  - сколько раз он «не успел» (не прошёл),
  - средняя позиция.
- Итоговая очередь формируется по алгоритму, учитывающему историю

#### ФТР-5 — Персонализация (реальные имена)
- Пользователь может установить/сменить своё реальное имя с помощью команды `/changename @username НовоеИмя`.
- При выводе очереди отображается имя + ник (из БД).

### 3.2. Нефункциональные требования (НФТР)

#### НФТР-1 — Надёжность
- Используется локальная база SQLite (`app.db`) с автоматическим созданием таблиц при старте.
- Бóльшая часть операций через транзакции.

#### НФТР-2 — Производительность
- Система должна поддерживать одновременную работу не менее 20-30 пользователей в чате.

#### НФТР-3 — Безопасность
- Токен бота хранится в .env.
- Логируется только служебная информация и ошибки.
- Администрирование через список `SUPER_ADMINS`.

#### НФТР-4 — Поддерживаемость
- Логика должна быть разбита на модули:
  - handlers — хэндлеры команд
  - db — модель и запросы в БД
  - services — бизнес-логика формирования очереди
  - config.py — загрузка конфигурации окружения
- Код оформлен с использованием PEP8 и типизации (Python 3.11+ рекомендуется).

## 4. Структура системы (архитектура)

### 4.1. Компоненты

1. **Telegram Bot (aiogram)**  
   - Точка входа: bot.py.

2. **Хэндлеры**  
   - admin.py — основная логика команд/кнопок.

3. **Слой данных**  
   - init_db.py — модель данных (SQLAlchemy ORM).
   - db.py — инициализация подключения и доступ к сессии.
   - queries.py — функции для операций CRUD.

4. **Сервис «Менеджер очереди»**  
   - queue_manager.py — формирование итоговой очереди, сортировка с учётом истории.

5. **Конфигурация**  
   - Используется .env.
   - Ключи: `BOT_TOKEN`, `SUPER_ADMINS`, `LOG_LEVEL`, `LOG_FORMAT`.

## 5. Требования к данным и БД

### 5.1. Модель данных

#### Таблица `subject`
- `id`: PK
- `chat_id`: id чата
- `subject_name`: уникальное название предмета

#### Таблица `queue`
- `id`: PK
- `subject_id` → subject.id
- `chat_id` → subject.chat_id
- `message_id`: id сообщения в Telegram
- `lesson_date`: дата занятия
- `close_at`: время закрытия 
- `status`: статус очереди
- `usernames`: JSON (список Telegram юзернеймов)

#### Таблица `users`
- `id`: PK
- `tg_username`: уникально
- `user_id`: Telegram id (уникально)
- `real_name`: свободный текст
- `is_admin`: булево
- `chat_id`: id чата

#### Таблица `queue_history` (SubmissionAttempt)
- `id`: PK
- `tg_username` → users.tg_username
- `subject_id` → subject.id
- `history_position`: JSON (список позиций)
- `missed_attempts_count`: int

#### Таблица `pay` (планы/подписки)
- `id`, `user_id`, `status`, `date_pay`, `date_end`

### 5.2. Ввод/вывод данных
- Ввод: команды Telegram, нажатия на inline-кнопки.
- Вывод: тексты/сообщения в чат, обновление inline-клавиатур, логи.
